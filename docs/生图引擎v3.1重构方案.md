> 2026-09-18。前置：engine v3（P1–P4，2026-09-13 已部署）。
> 本次针对三个仍然存在的痛点做收尾重构，不做推倒重来。

- 服务器已运行 v3 代码（a13114c），健康检查正常；`GENERATE_ALLOW_MOCK=false`，FC 转存已配置。
- `engine_jobs` 为 0 行：v3 上线后没有任何真实生图流量；nginx 近期日志只有扫描器流量。
- 旧架构 `legacy_generate_jobs` 共 175 条，失败 85 + 部分失败 4，**失败率约 51%**，最后一条 2026-08-31。用户抱怨的"经常返图失败"来自旧架构历史表现；v3 尚未经生产验证。

## 1. 痛点 → 对策

| 痛点 | 根因 | 对策 |
| --- | --- | --- |
| 后台配置臃肿 | `generation_providers` 35 个平面列与 config JSON 双轨并存；表单一次铺开 27+ 字段；模型精度档前端硬编码 | 删平面列（config JSON 唯一权威）；表单改"预设 + 基础/高级分层折叠"；精度档从后端 meta 下发 |
| 配置不可信 | 只有 12s 连通性探测，映射/转存链路无法验证 | 新增**试运行**：真实走一条完整生图链路（提交→上游→FC 转存→OSS→CDN），逐步展示耗时与产物 |
| base64/url 混乱 | v3 已在架构层收敛（FC 边界 + OSS 单出口），残留：settling 阶段小程序直接依赖上游临时 URL，微信 downloadFile 白名单不含上游域名 → "成功但显示失败" | 小程序端：临时图渲染失败兜底占位；预览/保存等 downloadFile 操作只允许永久 CDN URL；请求全局超时 |
| 返图失败率高 | 旧架构病灶已由 v3 解决；残留：KIE 回调弱鉴权、FC token 普通比较、maybeBilled 即失败、FC 未配置时静默走 API 服务器带宽 | 回调 per-job HMAC 签名 + timing-safe 比较；FC 未配置时启动告警 + 后台横幅；上游错误文案归一化（套娃 JSON / HTML 网关页） |

## 2. 后端改动（apps/api）

### 2.1 配置单轨化
- 迁移 `202609180001_engine_v31_single_track`：
  - 防御性回填：`config IS NULL` 的行由平面列构造 JSON；`config.adapter` 非法时按平面列映射修正。
  - `generation_providers` 删除 29 个平面配置列，仅保留 id/name/groupName/apiKeyEnv/apiKeyEncrypted/enabled/sort/config/时间戳；`config` 置 NOT NULL。
  - `engine_jobs` 增加 `dryRun Boolean @default(false)`。
- `provider-config.ts`：删除 legacy 回退，config JSON + 适配器默认值合并成唯一读取路径；默认值常量与 admin 共用（单一出处）。
- `admin-engine.service.ts`：停止双写；保存时仅写 config JSON。

### 2.2 试运行（dry-run）
- `POST /admin/engine/platforms/:id/dry-run`：用系统用户（openId `system:engine-dry-run`，懒创建）建一条 `dryRun=true` 的真实 EngineJob（1K/1:1/1 张，costCredits=0，billingState=settled），复用 `submitJob` 全链路（含 FC 生成或 FC 转存路径）。
- `GET /admin/engine/dry-runs/:jobId`：返回阶段化结果（提交/上游/转存指标/CDN URL/失败分类）。
- 账务守卫：`settleWithDrafts`/`settleTransferredJob` 对 dryRun 任务跳过草稿作品与 worksCount；退款天然为 0。
- 统计守卫：平台健康度排除 dryRun attempts；watchdog 每轮清理 3 天前的 dryRun 任务（≤5 条）。
- mock 开关打开时试运行走 mock 产物（本地开发验证管路用）。

### 2.3 安全与稳定
- KIE 回调：下发 callbackUrl 时附 `jobId + sig`（HMAC-SHA256(CALLBACK_SECRET, jobId)），校验用 timingSafeEqual；保留共享 secret 兼容；回调 taskId 必须属于该 job。
- FC token 比较改 timingSafeEqual。
- `matchesToken`/回调在 CALLBACK_SECRET 未配置且 NODE_ENV=production 时拒绝（非生产放行并告警）。
- FC 未配置且 NODE_ENV=production：启动时 error 级日志告警；`/admin/engine/health` 返回 `imageTransferConfigured`，后台页横幅提示。
- 上游错误文案归一化：`requestJson` 解套娃 JSON 错误、识别 HTML 网关错误页，截断 300 字符。
- admin engine 平台端点补 class-validator DTO。
- `/admin/engine/meta` 增加 `qualityTiers`（由 quality_configs 标签提取 1K/2K/4K，前后端同源）。

## 3. 管理后台改动（apps/admin）

- `OpsApiProvider.tsx` 重做：
  - 列表卡片瘦身：名称 + 启用开关 + 成功率状态点 + 协议/密钥/关联模型徽章 + baseUrl 一行；3 格统计、返回模式、尺寸摘要等移入编辑抽屉。
  - 新增流程改为**先选预设**（KIE 任务协议 / OpenAI 兼容 / Gemini / 通用 HTTP），预设填充全部默认值，典型平台只需填 Base URL + Key。
  - 表单分层：基础信息常显；"高级配置"折叠分组（端点/鉴权/结果/参考图/尺寸/参数/模板/映射），显示非默认项计数。
  - 每平台**试运行**按钮 + 阶段化进度面板（提交→生成→转存→CDN 图片预览），2s 轮询、5 分钟超时。
  - FC 未配置横幅。
- `OpsModel.tsx`：精度档从 meta 读取；线路编辑器加"复制到全部精度档"。

## 4. 小程序改动（apps/mobile）

- `services/api.ts`：uni.request 全局 `timeout: 20000`。
- 创作页结果卡片：`<image>` 加 @error 兜底——临时图失败显示"原图保存中"占位（继续轮询），永久图失败显示"加载失败，点击重试"（重拉任务获取新签名 URL）。
- 预览/放大/保存：temporary 资产一律 toast 提示"高清原图保存中"，不调用 getImageInfo/downloadFile/previewImage（上游临时域名不在微信白名单，必失败）。
- 轮询器：网络错误退避封顶 15s，永不把"查询失败"当"任务失败"（保持现有语义）。

## 5. 部署与验收

1. 本地：三端构建 + api 单测/集成测试。
2. 服务器：pg_dump 备份 → git pull → build → `prisma migrate deploy` → 修正 `KIE_CALLBACK_URL=https://ejoyflie.cloud/api/engine/callbacks/kie` → 重启 → health。
3. admin 静态构建发布到 `/var/www/admin`。
4. 生产验收：对真实平台执行试运行（url 模式与 base64 模式各一），核对 CDN 图片可访问、转存指标落库；检查 watchdog 无错误日志。
5. 小程序构建通过；发布需用户在微信开发者工具上传提审（线上小程序为旧版时生图入口不可用，需尽快发新版）。

## 6. 不做的事

- 不再引入旧 `/generate/*` 兼容层：8-31 后旧接口零流量，无存量在线客户端依赖。
- 不改 maybeBilled 保守退款策略（避免双倍上游计费是明确设计原则），仅改善文案与错误归一化。
